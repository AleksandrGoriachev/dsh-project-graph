# Роадмап: обмен и канбан-воркспейс

## Симптом

`check-exchange` показывал непрочитанные письма от `dsh-kanban-board`; письмо висело «ждёт вручения: gate:invited», после принятия папки появилось три непрочитанных: приглашение и две побайтовые копии одного отчёта (общий ящик хаба и папка воркспейса).

## Причины

1. **Контракт folder-2 был с пустым `Invited:`.** Папка добавлена, когда `structure` ещё не была участником; `action=update` намеренно не переписывает существующий контракт, поэтому приглашение не появилось и папка осталась непринятой. Письмо ждало `gate:invited`.
2. **Канбан-воркспейс не был в roots/participants сторожа** на момент отправки; отчёт положили копией в общий ящик хаба, а не только в папку. После перезапуска roots/participants включают `dsh-kanban-board`, но папка всё ещё не была принята.
3. **Одно письмо лежало в двух ящиках.** Побайтовые копии считались двумя непрочитанными: дедупликации по содержимому не было.
4. **`gate:invited` письмо считалось непрочитанным**, хотя доставить его было нельзя; отдельного действия «принять папку» в check-exchange не было.
5. **`exchangeAttention` считает копии по одной** (N3 ревью 0322): «непрочитано 1», а «требуют хода 2».
6. **Структура канбана живёт в сторе** `~/.dsh/project-graph/dsh-kanban-board-934d448d/graph.json` — это правильно: структура не принадлежит repo проекта. Материализация в repo была ошибкой и удалена.
6. **В структуре канбана предупреждения:** у coordinator нет модели и prompt, у worker-1 нет prompt, у всех узлов `anchors.consumes: []`; рёбра reviewer→coordinator (delegate), reviewer→worker (report) требуют подтверждения владельца.

## Сделано (фаза 0–1)

- `folder-2`: контракт переиздан (Rev 2, `Invited: structure`), папка принята (`join`), квитанция `threads/structure/...--structure--01.md` записана.
- Письма (приглашение и две копии отчёта) разобраны и отмечены; `непрочитано: 0`.
- **0322 принят:** `scanExchange` кладёт `sha256` и дедуплицирует unread по содержимому; `--mark` одной копии снимает все; recovered тоже дедуплицируется. HEAD `e67f73a`.
- Структура канбана остаётся в store (5 узлов, 2 папки, 0 ошибок; 3 предупреждения); repo проекта не тронут.

## Фазы

### P2. Жизненный цикл папки — **готово (0323)**
- 0323: update при изменении participants переиздаёт контракт (Rev+1) и приглашает добавленных; add сразу пишет Invited и приглашения.
- Store-структура создаётся автоматически при первом GET /api/graph: явный coordinator, repo не трогается.
- Тест: добавили папку без structure → добавили structure → приглашение появилось, gate снят.

### P3. Внимание и доставка — **готово (0322 + 0325)**
- 0325: exchangeAttention дедуплицирует копии по sha256; answer на одну копию снимает все; «требуют хода» = «непрочитано».
- `gate:invited` показывать отдельной строкой «ожидает принятия папки» с действием accept/join, а не только порогом unread.
- Автотест recovered-дедупликации (N2) и negative-кейс C1 с разным телом (N1).

### P4. Структура канбана (store)
- Владельцу: заполнить модель/prompt coordinator, prompt worker-1, привязать якоря или явно оставить пустыми; подтвердить/исправить рёбра reviewer→coordinator и reviewer→worker.
- Канонический источник структуры — store `~/.dsh/project-graph/<проект>-<хеш>`; repo проекта не получает `structure/` (материализация удалена).

### P5. Канбан-доска MVP (по docs/ANALYSIS.md §13)
- `board/epics`, `board/tasks`, `board/journal.jsonl`, `.sweep.json`; единственная операция `apply(card, from, to, proof)`.
- Письма-маркеры `[task-accept]`, `[stage-ready]`, `[stage-accepted]`, `[blocked]`, `[scenario-failed]`.
- MVP — ритуал сессии архитектора через `exchange-inbox`/`check-exchange`; позже watcher в host-половине панели.

### P6. Неизменяемые спеки узлов (бэклог 20)
- Этап 2 специфицирован; этап 3 (код) ждёт команды: ядра в коде, class/specHash, addendum, fail-closed, две связи аудитора.

## Критерий завершения

Новое письмо из канбана доставляется без ручной копии в общий ящик, `непрочитано` и «требуют хода» совпадают, папка принимается один раз, структура канбана живёт в store и не попадает в repo, доска движется по письмам без ручной правки карточек.
