## 0. Что было и почему это не работало

Сегодня версии плагинов живут в двух несвязанных местах панели:

1. Строка «Версия · структура неизвестно · релиз не проверялся» с кнопкой «Проверить релиз» — она про
   релиз DSH, а не про плагины, и умеет только проверять.
2. Отдельная карточка «Workflow · не установлен · Плагин не установлен. Панель его не ставит… · движок:
   нет данных» с кнопкой «Проверить Workflow» — на всю ширину, толкает канву вниз.

Итог: обновить нельзя ни один плагин; «неизвестно» и «не проверялся» — не состояния, а отсутствие данных;
причину ошибки некуда положить; порядок, если обновления есть у обоих, не задан.

## 1. Где живут — отдельная полоса под шапкой панели

Выбрана полоса 38 px во всю ширину, сразу под шапкой панели (46 px):
два блока рядом (structure слева, workflow справа), справа — «Проверить всё».

Почему не шапка и не карточка версии:

- **Шапка панели** занята именем, меткой сборки и тремя действиями; два блока с версиями и кнопками там
  не помещаются, а вытеснять действия нельзя.
- **Карточка версии** (как сейчас с Workflow) занимает всю ширину, живёт в потоке и толкает канву вниз;
  при появлении обновления канва «прыгает» на её высоту.
- **Полоса** фиксированной высоты 38 не перестраивает раскладку при смене состояния, читается как
  «состояние инструментов», а не как «ещё один блок работы».

Как не конфликтует с вкладкой валидатора: вкладка — внутри канвы у карточки координатора (14 × 44),
полоса — выше канвы и вне её прокрутки. Разные родители, разные слои, общий только правый край панели.
С верхней панелью A (хост DSH) — тоже: полоса начинается ниже границы панели Structure и не занимает
хост-шапку.

## 3. Кнопки: что доступно и почему disabled

| Кнопка | Когда активна | Почему disabled в остальных случаях (title) |
| --- | --- | --- |
| Проверить снова | всегда, кроме «обновлено» | «идёт проверка реестра» / «перезапуск DSH перезагрузит плагин» |
| Обновить | только state = «доступна» | «нет новой версии: 1.0.56 — последняя известная» / «пока проверка не закончилась, обновлять нечего» / «store v10 ≠ v11 — выполните pnpm install» / «сеть недоступна — обновление невозможно» |
| Перезапустить DSH | только после обновления | появляется вместо «Обновить»; одна на оба блока — перезапуск один |
| Проверить всё | всегда | — (проверяет оба блока, не мешает частным кнопкам) |

Правило: у каждой disabled-кнопки есть title с причиной. Кнопка не «серая без объяснений».

## 4. Порядок при двух доступных обновлениях

1. Блоки всегда в одном порядке: **structure** слева, **workflow** справа — не по «кто первый обновился».
2. «Обновить всё» идёт **по очереди, structure первой**: пока панель старая, она же неверно показывает
   состояние workflow.
3. Ошибка соседа не блокирует: workflow в ошибке не мешает обновить structure, и «Обновить всё» честно
   говорит, что обновит один из двух.
4. Перезапуск — один на пачку: одна кнопка и одно сообщение, а не по кнопке на блок.

## 7. Было / стало — коротко

1. Две разрозненные строки (версия релиза + карточка Workflow) → одна полоса с двумя блоками рядом.
2. Кнопки только «Проверить» → «Проверить снова» / «Обновить» / «Перезапустить DSH» по состоянию.
3. Два фактических состояния («неизвестно», «не установлен») → пять, включая «идёт проверка» и «ошибка с причиной».
4. Причине ошибки негде было жить → короткая на полосе, дословная в поповере + «что сделать».
5. Порядок не задан → structure → workflow, «Обновить всё» по очереди, один перезапуск.
6. Карточка на всю ширину толкала канву → фиксированные 38 px и чип на узкой панели.

## 8. Правки для воркера

1. Убрать строку «Версия · …» и карточку Workflow, добавить компонент renderUpdatesBar() под шапкой панели.
2. GET /api/updates → { blocks: [{ id, name, installed, available, state, reason, checkedAt }] },
   state: 'ok' | 'new' | 'checking' | 'error' | 'updated'.
3. Порядок блоков фиксированный: ['structure','workflow'], не порядок ответа.
4. «Обновить» активна только при available && state === 'new'; у каждой disabled — title с причиной.
5. POST /api/updates/check с таймаутом 15 с; checking — только на своём блоке.
6. POST /api/updates/apply по одному блоку; «Обновить всё» — последовательность, structure первой,
   один итоговый «перезапустите DSH».
7. Хранить состояние в structure/updates.json (вне graph.json), чтобы оно переживало закрытие панели.
8. Медиа-правила 1100 / 1000 / 760; высота полосы 38 всегда.
9. z-index: полоса ниже меню (46) и модальных окон (60), поповер 40; канву не перекрывать.
10. Тесты: [data-updates-bar], [data-update-block="structure|workflow"], [data-update-state];
    проверки на порядок блоков и на title у каждой disabled-кнопки.
