## 1. Проблема

1. **Свёрнутая палитра не запоминается.** Человек свернул её, чтобы схеме было шире,
   перезагрузил — палитра снова 250 px. Каждый вход начинается с одного и того же
   сворачивания.
2. **Свёрнутая палитра теряет имя.** Остаются три плашки с типом (`critic`, `worker`,
   `folder`) и кнопка-стрелка (символ «» вправо) в заголовке. Что это за полоса — видно только по
   трём словам; сама полоса ничего не называет, а стрелка — единственный орган
   разворачивания, хотя вся полоса и есть палитра.
3. **Граница воркспейса — картинка, а не орган управления.** Она жёстко прибита к
   крайней карточке (+20 px), зона «вне» всегда начинается в 48 px за ней. Человек не
   может ни отдать зоне «вне» больше места, ни забрать его назад.
4. **Несколько папок обмена не имеют своего органа.** Порталы растут только вниз: при
   трёх папках лента уходит за нижний край канвы, а ширину канвы это не меняет.
   Правило заказчика «больше одного элемента — панель уходит вправо, разделитель это
   компенсирует» сейчас выразить нечем.

## 2. Решения (пять, дальше — подробно)

| № | Решение | Почему |
| --- | --- | --- |
| 1 | Свёрнутая палитра — **корешок книги**: полоса 44 px, вертикальная надпись «Набор узлов структуры», чтение сверху вниз; ни галочки, ни стрелки | Название возвращается в свёрнутое состояние; корешок на полке читается без открывания книги; полоса остаётся палитрой, а не кнопкой |
| 2 | Три карточки в полосе — **иконки 32 × 32** с полосой роли; их по-прежнему можно тянуть и брать с клавиатуры | Работа с полной канвой — это ровно тот случай, когда палитра свёрнута; прятать вынос значило бы заставлять разворачивать её обратно |
| 3 | Состояние «развёрнуто/свёрнуто» **запоминается** в браузере; читается синхронно до первого кадра | Ноль сетевых запросов и ноль мигания; это предпочтение человека, а не факт проекта |
| 4 | Барьер — **перетаскиваемая граница**: `outside` (просвет между крайней карточкой и пунктиром) задаётся мышью и клавиатурой, хранится на воркспейс | Сейчас это константа 20; человек получает орган вместо картинки, и просвет — единственная часть зоны «вне», которую действительно можно менять (портал 236 px фиксирован) |
| 5 | Несколько папок: **вторая колонка порталов** шириной 236 + 16, если видимая часть канвы это вмещает; иначе одна колонка | Правило «больше одного элемента уводит панель вправо» выполняется буквально; разделитель компенсирует: тянем вправо — просвет растёт, колонка складывается, схеме возвращается 252 px |

## 3. A. Свёрнутая палитра — «корешок книги»

### 3.1 Анатомия

```
     44 px
   ┌──────┐
   │      │  ← 8 px верхний отступ
   │  Н   │
   │  А   │  корешок: writing-mode: vertical-rl,
   │  Б   │  uppercase, 11 px / 600 / трекинг 0.12em,
   │  О   │  цвет T.secondary, чтение СВЕРХУ ВНИЗ
   │  Р   │
   │      │
   │  У   │
   │  З   │
   │  Л   │
   │  О   │
   │  В   │
   │      │
   │  С   │
   │  Т   │
   │  Р   │
   │  У   │
   │  К   │
   │  Т   │
   │  У   │
   │  Р   │
   │  Ы   │
   │      │  ← гибкий зазор (flex: 1)
   │ ⚖ ▍  │  ← 32 × 32, полоса роли 4 px слева
   │ ⚙ ▍  │     (критик #f59e0b / воркер #3b82f6 / папка #10b981)
   │ 📁▍  │
   │      │  ← 8 px нижний отступ
   └──────┘
   страница книги: 3 px полоса справа во всю высоту
```

Слева — рабочая часть корешка, справа — «обрез страниц» (декоративная полоса
`linear-gradient(90deg, transparent, var(--dsw-alias-bg-layer-2))`, `aria-hidden`).
Она и говорит «за полосой целая книга», не рисуя ни стрелки, ни галочки.

### 3.2 Метрики

| Что | Значение | Токен / как задаётся |
| --- | --- | --- |
| Ширина полосы | **44 px** (`flex: 0 0 44px`) | было 48: полоса больше не держит двухстрочные плашки |
| Внутренние отступы | 8 px сверху и снизу, 6 px слева и справа | `padding: 8px 6px` |
| Фон, скругление, тень | как у развёрнутой панели | `var(--dsw-alias-bg-base, #fff)`, `border-radius: 16px`, `box-shadow: 0 8px 22px rgb(20 20 45 / 6%)` |
| Рамка | нет | панель и полоса — одна и та же карточка, свёрнутая пополам |
| Надпись | 11 px, 600, uppercase, `letter-spacing: 0.12em`, `line-height: 1.2` | `writing-mode: vertical-rl`; `text-orientation: mixed` (кириллица поворачивается целиком) |
| Цвет надписи | `T.secondary` (`var(--dsw-alias-label-secondary)`), hover — `T.text` | `lib/client.js:38–51` |
| Длина надписи | «НАБОР УЗЛОВ СТРУКТУРЫ», 21 знак ≈ **184 px** | 11 px Segoe UI + 1.32 px трекинга |
| Кнопка надписи | `flex: 1 1 auto; min-height: 0; padding: 10px 0`, прозрачная | вся свободная высота полосы — одна кнопка «развернуть» |
| Обрез страниц | 3 px, справа, во всю высоту | `aria-hidden`, hover → `T.border1` |
| Иконки | 32 × 32, скругление 8, фон `#efeff3`, рамка 1 px `T.border2`, глиф 14 px по центру | 3 штуки, gap 6 px, прижаты к низу |
| Полоса роли на иконке | 4 px, слева, во всю высоту, скругление 2 | `libraryRoleColor(type)`: `#f59e0b`, `#3b82f6`, `#10b981` |
| Кольцо фокуса | 2 px `T.link`, `outline-offset: -3px` (внутри полосы) | клавиатура не выводит фокус за край |

Ширина 44 выбрана из расчёта: 44 − 2 × 6 = 32 px на иконку, при этом надпись 11 px
читается в 12-пиксельной строке с запасом 4 px по сторонам.

### 3.3 Направление чтения — сверху вниз

`writing-mode: vertical-rl` **без** `rotate(180deg)`: буквы повёрнуты на 90° по
часовой, строка идёт от верхнего края к нижнему.

- так читаются корешки русских книг на полке — метафора заказчика соблюдена;
- глаз входит в панель сверху, там же и начало слова;
- нет `transform`, значит нет субпиксельного размытия букв и нет второго «слоя»
  правок в `transform-origin` при смене ширины.

Обратный вариант (`vertical-rl` + `rotate(180deg)`, чтение снизу вверх) —
в §9 как открытый вопрос, а не как скрытая альтернатива: менять направление дёшево,
но выбрать надо один раз.

### 3.4 Высота панели и обрезка

Свободная высота под надпись: `L = H − 8 − 8 − (3 × 32 + 2 × 6) − 10 − 20` (отступы полосы,
три иконки, зазор до них, внутренние отступы кнопки), то есть `L = H − 154`.

| Высота полосы H | L | Что видно (проверено в макете) | Почему так |
| --- | --- | --- | --- |
| 420 px | 266 | «НАБОР УЗЛОВ СТРУКТУРЫ» целиком (184 px), по центру | обычный рабочий экран |
| 300 px | 146 | «НАБОР УЗЛОВ СТРУК…» с многоточием | 184 не влезает; обрезка честнее уменьшения шрифта |
| 220 px | 66 | «НАБОР У…», полное имя — в `title`/`aria-label` | это минимальная высота канвы (`S.canvas.minHeight: 220`); 21 знак туда не влезет ни при каком кегле |
| < 190 px | < 36 | надпись скрыта, остаются иконки и обрез страниц | двухбуквенный корешок — шум; кнопка жива, `aria-label` полный |

Правила: **обрезка с многоточием, а не прокрутка** (скроллбар в 44 px уродует полосу
и крадёт 12 px) и **не уменьшение шрифта** (11 px — уже минимум читаемости).
Обрезка целиком на CSS: `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`
— вертикальный `ellipsis` работает в Chromium при `writing-mode`. Никаких
`ResizeObserver` и замеров: раскладка не должна зависеть от JS.

Полная надпись всегда доступна словами: `title` и `aria-label` кнопки.

### 3.5 Три карточки в полосе

- **Остаются**, как иконки 32 × 32: ⚖ критик, ⚙ воркер, 📁 папка. Это и есть ответ на
  «скрыты или иконки»: скрывать нельзя — полная канва и свёрнутая палитра нужны
  одновременно именно тогда, когда человек ставит узлы.
- Иконка — та же кнопка, что карточка: `pointerdown` начинает перенос
  (`beginPointerCarry`), `Enter` берёт карточку с клавиатуры (`beginKeyboardCarry`),
  `aria-label` — прежний, полный (роль, связь по умолчанию, расписание, «папка — не агент»).
- `title`: «Критик — возврат report координатору · ежедневно 09:00».
- Роль видна цветом полосы и словом в `aria-label`/`title`, а не только цветом.
- Если у карточки нет иконки (будущий элемент) — глиф-заглушка «＋» 14 px, тот же
  размер плитки, чтобы полоса не «прыгала».

### 3.6 Состояния полосы

| Состояние | Надпись | Полоса | Обрез страниц | Ещё что |
| --- | --- | --- | --- | --- |
| Покой | `T.secondary` | фон панели | `bg-layer-2` | курсор `pointer` на кнопке надписи |
| Hover кнопки | `T.text` | `T.bg1` у кнопки, скругление 12 | `T.border1`, 4 px | `title`: «Развернуть набор узлов структуры — панель 250 px» |
| Focus (Tab) | `T.text` | кольцо 2 px `T.link` внутри | `T.border1` | фокус на кнопке надписи, а не на полосе |
| Нажатие | `T.text` | `T.bg2` у кнопки | — | срабатывает по `click`, не по `pointerdown`: перенос карточки не должен разворачивать панель |
| Иконка: hover | — | рамка `T.link`, тень `0 0 0 3px rgb(65 118 230 / 14%)` | — | курсор `grab` |
| Иконка: drag | — | `opacity: .55`, курсор `grabbing` | — | призрак карточки — прежний |

Переходы: только фон и цвет, 120 ms. **Ширина не анимируется** — иначе канва
дёргается 120 ms и SVG пересчитывается в каждом кадре.

### 3.7 Запоминание состояния

|Что | Значение |
| --- | --- |
| Где | `window.localStorage`, ключ `dsh.project-graph.ui.v1` (один JSON на всю панель) |
| Формат | `{ v: 1, libraryOpen: boolean, outside: { "<абсолютный корень>": number } }` |
| Первый вход | развёрнуто (`libraryOpen: true`): человек должен увидеть, что это за палитра |
| Нет ключа / битый JSON / чужой `v` | развёрнуто, без сообщений об ошибке |
| Хранилище запрещено (приватный режим, iframe) | значение живёт в памяти на время сеанса, панель работает как обычно, никакой плашки об ошибке |
| Запись | на переключение — сразу; ошибка записи глушится |
| Область | **на браузер, не на воркспейс**: это место на экране, а не факт проекта; при смене проекта панель не должна перещёлкиваться |

**Как избежать мигания при восстановлении** (три конкретные меры):

1. Чтение — **синхронно, до первого кадра**: `useState(() => readPanelPrefs().libraryOpen ?? true)`.
   Никаких `useEffect` для восстановления: эффект срабатывает после отрисовки, и
   человек успевает увидеть 250 px, которые через кадр станут 44.
2. Первая отрисовка уже правильная: ширина `44`/`250` берётся из того же состояния, а не
   из класса, который навешивается потом, — канва не пересчитывает SVG на монтировании.
3. **Нет `transition` на ширину** палитры. Анимация ширины на монтировании — это и есть
   мигание: она проигрывается от дефолта к сохранённому значению.

Тот же приём — для барьера, но там значение привязано к корню, поэтому оно
подставляется в рендере при первом же `payload.root` (React-паттерн «adjust state
during render»: `if (rootRef.current !== payload.root) { rootRef.current = payload.root;
setOutside(readOutside(payload.root)); }` — `setState` в рендере того же компонента
перерисовывает до коммита, вспышки нет).

### 3.8 Доступность

- Кнопка корешка: `<button type="button">`, `aria-expanded="false"`,
  `aria-controls="pg-library-items"`, `aria-label="Развернуть набор узлов структуры"`.
  `id="pg-library-items"` есть в DOM всегда: в свёрнутом состоянии контейнер скрыт стилями, но
  не удалён, поэтому `aria-controls` не висит в пустоте, а разворот его же и показывает.
- `Enter` и `Space` разворачивают (поведение кнопки); фокус остаётся на том же органе —
  кнопка «Свернуть» в шапке развёрнутой панели — и следующий `Tab` ведёт к карточкам.
- Иконки — отдельные кнопки в порядке Tab: ⚖ → ⚙ → 📁; `aria-label` полный; `title` дублирует.
- `aria-live` (существующий `setLive`): «библиотека узлов свёрнута: схема получила больше
  места» / «библиотека узлов развёрнута».
- Кольцо фокуса видимое у всех трёх органов; `prefers-reduced-motion` не отменяет
  ничего важного (анимаций ширины нет).
- Многоточие не влияет на чтение скринридером: `aria-label` всегда полный.

### 3.9 Сколько узлов в структуре

Палитра — всегда три карточки (заказчик: «палитра остаётся палитрой трёх карточек»).
Число узлов на канве на корешок не влияет:

| Узлов | Палитра свёрнута | Что видно |
| --- | --- | --- |
| 0 | да | корешок и три иконки; вынос из иконки работает, канва принимает первый узел |
| 1 | да | то же; граница воркспейса проходит по единственной карточке |
| много | да | то же; высота полосы равна высоте канвы, надпись обрезается по §3.4 |

## 4. B. Барьер «воркспейс | вне»

### 4.1 Что сейчас

`borderX = width + 20`, где `width` — правый край самой правой карточки;
`portalX = borderX + 48`; порталы 236 px стоят лентой вниз; канва расширяется до
`portalX + 236`. Граница — две линии и две подписи в SVG, Pointer-событий у неё нет.

### 4.2 Новая геометрия

```
cardsRight = max(x + w)                    // крайняя карточка, как и сейчас
outside    = 20 … 360, default 20, шаг 8   // просвет: карточка → пунктир (новое, хранится)
borderX    = cardsRight + outside          // пунктир
portalX    = borderX + 48                  // первый столбец порталов, PORTAL_GAP не меняется
cols       = (N ≥ 2 && visible ≥ 536) ? 2 : 1
visible    = canvasClientWidth − borderX − 16
zoneWidth  = 48 + cols·236 + (cols−1)·16   // 284 или 536
svgWidth   = max(width, portalX + cols·236 + (cols−1)·16) + 2·16
```

`outside` — ровно то число, которое задаёт разделитель. Оно и есть «сколько места
отдано зоне «вне» до её содержимого»: сам портал фиксирован (236 px, §«что не менять»),
поэтому единственная управляемая часть зоны — просвет; он же решает, влезает ли
вторая колонка.

### 4.3 Состояния: 0, 1, много

**0 папок обмена** (прежний единственный портал «Выход вне» с пустым состоянием или
со связями из `/api/exchange`):

```
 ┌──────┐ ┌──────┐        ┊  ┌────────────────┐
 │co-ord│ │worker│        ┊  │ Выход вне      │

 ┌──────┐                 ┊  │ папок обмена   │
 │judge │                 ┊  │ не найдено     │
 └──────┘                 ┊  └────────────────┘
     ↑ 20 px ──────────────┘        ↑ 48 px
   outside=20                      колонка 1
```

Зона всё равно существует и тянется: это граница воркспейса, а не портал.
Подпись в зоне: «обмена нет — причина и рецепт», как сейчас.

**1 папка обмена:**

```

 ┌──────┐ ┌──────┐        ┊  ┌──────────┐  ┌──────────┐
 │co-ord│ │worker│        ┊  │ папка A  │  │ папка B  │
 └──────┘ └──────┘        ┊  │ ↗ 12 ↙ 9 │  │ ↗ 3 ↙ 0  │
 ┌──────┐                 ┊  └──────────┘  └──────────┘
 │judge │                 ┊  ┌──────────┐
 └──────┘                 ┊  │ папка C  │
                          ┊  └──────────┘
                          ┊   зона 536 px, 2 колонки
```

**Много папок, места мало — одна колонка:** то же, что «1 папка», но порталы идут
лентой вниз через 26 px. Канва не обрезает: если лента выше канвы, канва растёт в
высоту и прокручивается.

### 4.4 Линии при двух колонках

- Колонка 1 — как сейчас: линия входит в левый край, на высоте середины портала
  (`portalStart`/`portalRoute` без изменений).
- Колонка 2 — вход **в верхний край**: линия идёт по свободной горизонтальной полосе
  между рядами карточек, поднимается в зазоре `borderX … portalX`, идёт по полосе
  `y = −8` **над** всеми порталами и опускается в верхнюю грань нужного портала.
  Так линия никогда не пересекает колонку 1 и не проходит по тексту.
- Подпись «последнее: …» остаётся только у одиночного портала (как сейчас: у ленты
  подписи легли бы друг на друга; направление показывает наконечник, даты — в карточке).

### 4.5 Перетаскивание

| Что | Как |
| --- | --- |
| Захват | невидимый `<rect>` 12 px по ширине (touch — 24 px) на `borderX`, от `−14` до `height + 14`; `cursor: col-resize`; `touch-action: none`; `pointer-events: all` |
| Видимый орган | риска: `<rect>` 6 × 36, `rx 3`, фон `var(--dsw-alias-bg-base,#fff)`, рамка `T.border2`, внутри три точки по 1 px — не стрелка и не иконка, а книжная закладка |
| События | `pointerdown` → `setPointerCapture`, запоминаем `startX = e.clientX`, `startOutside`; `pointermove` — масштаб 1 (viewBox совпадает с CSS px), `outside = snap8(startOutside + dx)`, зажим `[20, 360]`; `pointerup`/`pointercancel` — фиксация, сохранение, `aria-live` один раз |
| Отмена | `Esc` во время переноса — вернуть `startOutside`, ничего не сохранять |
| Привязка | сетка 8 px **от минимума**: 20, 28, 36… (иначе сам минимум 20 недостижим: округление давало 24); `Shift` во время переноса — 1 px без сетки |
| Частота | пересчёт в `requestAnimationFrame`, запись в хранилище — `debounce 200 ms` и сразу на `pointerup` |
| Порталы и линии | следуют за линией в том же кадре (они считаются от `borderX`); линия не отрывается от портала, подписи едут вместе с порталом |
| Складывание колонок | **только на `pointerup` и на `resize`** (с гистерезисом 24 px), не в середине переноса: иначе портал прыгает под курсором. Пока перенос идёт, число колонок заморожено тем, каким было на `pointerdown` |
| Двойной клик | `outside = 20` (сброс), с `aria-live` «граница воркспейса: 20 px, как при первом входе» |
| Касание | то же событие `pointerdown` с `pointerType: touch`; зона захвата 24 px; перенос не срабатывает, пока палец не сдвинулся на 4 px (чтобы касание не считалось переносом) |

Курсор: `col-resize` на зоне захвата; на карточках и порталах не меняется — зона
захвата не перекрывает ни карточки (они левее `borderX − outside`), ни порталы
(они правее `borderX + 48`).

Чем орган себя выдаёт (без стрелок и иконок):

- **риска** на пунктире — капсула 6 × 36 px у верхнего края, она и тянется;
- **чип в шапке канвы** — «вне: 284 px · 1 колонка», справа от чипов узлов и связей;
  он же показывает, что произошло после переноса;
- **строка подсказки** под канвой дополняется: «Границу воркспейса можно тянуть мышью;
  стрелки — 8 px, Shift — 1 px, Home — сброс на 20 px, двойной щелчок по риске — тоже сброс»;
- `title` на разделителе повторяет то же самое словами.

### 4.6 Клавиатура

Орган — `<g role="separator" tabindex="0">` (разделитель, у которого есть значение,
по ARIA — «window splitter»).

| Клавиша | Действие |
| --- | --- |
| `←` / `↓` | `outside − 8` (просвет уже, схеме шире) |
| `→` / `↑` | `outside + 8` (зона «вне» дышит) |
| `Shift` + стрелка | ±1 px |
| `Home` | 20 (минимум = сброс «как было») |
| `End` | 360 (максимум; перетаскиванием по сетке — до 356, `End` даёт крайнюю точку) |
| `Tab` | уводит фокус дальше; `Esc` во время переноса — отмена |

После каждого шага — короткое `aria-live`: «граница воркспейса: 28 px, зона «вне»:
1 колонка». Частые сообщения не спамят: `setLive` перезаписывает строку, а не копит.

### 4.7 Окно изменилось

- `outside` не меняется: это число пикселей, а не доля. Схема не «переезжает» сама.
- Пересчитываются `cols`, ширина и высота SVG, позиции порталов. Гистерезис 24 px:
  двухколоночный режим включается при `visible ≥ 536`, выключается при `< 512`.
- `scrollLeft` сохраняется; если содержимое сузилось меньше прокрутки — прокрутка
  мягко ужимается, скачка нет.
- Панель уже 720 px: палитра всё равно 250/44 (она не сжимается), канва
  прокручивается, порталы складываются в одну колонку.

### 4.8 Сохранение и сброс

| Что | Значение |
| --- | --- |
| Ключ | тот же `dsh.project-graph.ui.v1`, поле `outside[<абсолютный корень>]` — **на воркспейс**: у разных структур разная ширина |
| Первый вход | `20` — ровно сегодняшний вид (`PORTAL_BORDER_GAP`), макет ничего не сдвигает без человека |
| Запись | `debounce 200 ms` при переносе, сразу на `pointerup`, `Home` и двойной клик |
| Чтение | при первом `payload.root` (см. §3.7, без вспышки) |
| Сброс | двойной клик по риске, `Home` с клавиатуры; «Сбросить схему» его **не трогает** — это раскладка узлов, а не ширина панели |
| Битое/чужие данные | зажим в `[20, 360]`, иначе `20` |

### 4.9 Доступность

```
role="separator" tabindex="0" aria-orientation="vertical"
aria-label="Граница воркспейса и зоны «вне»"
aria-valuemin="20" aria-valuemax="360" aria-valuenow="20"
aria-valuetext="20 пикселей между схемой и зоной «вне»; 1 колонка порталов"
aria-controls="pg-workspace-pane pg-outside-pane"
```

- Фокус: линия становится сплошной `T.link` 2 px, риска — `T.link`; подпись «воркспейс»
  остаётся на месте, чтобы человек понимал, что тянет.
- Подписи «воркспейс» и «вне» — 9 px `T.caption`, у `y = −3`, как сейчас (они не
  декоративные: называют обе стороны).
- Значение озвучивается словами по-русски (`aria-valuetext`), а не как «25 процентов».
- `aria-controls` ссылается на две группы SVG, которым даются `id`: левая — карточки и
  связи, правая — порталы. Тогда скринридер знает, что именно меняет разделитель.
- `prefers-reduced-motion`: анимаций нет, кроме цвета.

## 6. Где хранится состояние — решение и цена

Выбрано `localStorage` (`dsh.project-graph.ui.v1`), потому что:

1. **Нет мигания**: чтение синхронное, до первого кадра. Серверный вариант требует
   `fetch` — первый кадр всегда дефолтный, потом «щелчок» в сохранённое состояние.
2. **Это предпочтение человека, а не факт проекта**: ширина панели не должна
   становиться частью структуры, попадать в git и в гейт задач.
3. **Ноль правок сервера**: `lib/api.js` и `lib/store.js` не трогаются.

Цена, которую надо принять явно: `test/client.test.mjs:435` запрещает строку
`localStorage` во всём `lib/client.js` — тест написан против хранения **раскладки** в
браузере («раскладка не живёт в браузере: только structure/*.json») и бьёт шире
своего смысла. Варианты:

- **A (рекомендуется).** Сузить проверку: запрет остаётся на путях раскладки
  (`saveLayoutPositions`, `/api/layout`), новый хелпер `readPanelPrefs/writePanelPrefs`
  явно назван «предпочтение панели». Тест правится вместе с реализацией, смысл теста
  сохраняется: x/y по-прежнему только в `structure/*.json`.
- **B.** Серверное хранилище (`/api/ui`, файл в store `~/.dsh/project-graph/<name>-<hash>/`).
  Тогда раскладка и предпочтения живут рядом, но появляется сетевой запрос и риск
  мигания; тест не трогается.

Пока макет на приёмке, решение A записано как требование к реализации, а не как
сделанный факт: без него палитра не сможет помнить состояние, не сломав тест.

## 9. Открытые вопросы

1. **Направление корешка.** Выбрано сверху вниз (корешок русской книги). Вариант
   «снизу вверх» (`vertical-rl` + `rotate(180deg)`) — одна строка CSS; нужно слово
   заказчика, чтобы не менять потом.
2. **Хранение.** Вариант A (§6) требует сузить проверку `localStorage` в тесте.
   Если «ничего в браузере» — это правило, а не случайность теста, нужен серверный
   `/api/ui` и тогда честно принять одно мигание на первом кадре.
3. **Вторая колонка порталов.** Правило «больше одной папки — панель вправо»
   реализовано колонками 236 + 16. Альтернатива — лента вниз с прокруткой и без
   второй колонки; тогда разделитель остаётся только просветом, и правило заказчика
   выполняется лишь частично. Нужен выбор до реализации маршрутов линий.
4. **Вход линии в верхнюю грань** для колонки 2 — единственный маршрут без
   пересечения колонки 1. Если он читается плохо, есть вариант входить в левый край
   через 16-пиксельную щель между колонками.
5. **Порог 536 px** зависит от ширины канвы в панели (сейчас ~980 px при 1280 px окна).
   Если реальная канва уже, двух колонок не будет почти никогда — тогда правило
   заказчика стоит перечитать как «одна колонка, но шире карточка портала».
6. **Счётчик в корешке.** Сейчас числа карточек в полосе нет: три иконки и есть
   счётчик. Нужен ли «3» рядом — вопрос вкуса, в макете не рисуем.
