## 2. Что именно переехало

Из нижней панели (`renderDetails()`) под правую кнопку уходят строки:

1. **Состояние** — слово и фраза-пояснение (`nodeState` + `stateSentence`).
2. **Источник активности** — живой агент / журнал сессии / журнал запусков.
3. **Отчёт** последнего запуска.
4. **Сессия-владелец** — привязка, «Привязать текущую», «Отвязать» (это действие,
   а не поле: выполняется сразу, без «Сохранить»).
5. **Расписание** — ежедневное время и следующий запуск (редактирование времени —
   во вкладке «Настройки», как в утверждённом окне 0018).
6. **Ветка** — шаги одного запуска `project_graph_branch`.

**Пресет** (сейчас показывается только в нижней панели) переезжает в настройки
окна — только для чтения: поля записи пресета у узла нет.

**Остаётся внизу:** узкая полоса на 56 px с действиями, которым нужна канва, —
«Связь» и «Запустить» (вызов `project_graph_run`/`project_graph_branch`, как
сейчас). Нижняя карточка с десятком строк исчезает: состояние больше не надо
искать и дочитывать.

**Не меняется:** на карточке остаются слово состояния, точка запуска и строка
следующего запуска — быстрый взгляд без открытия чего-либо. У папки обмена —
свой редактор и «только сообщения», вкладки состояния у неё нет.

## 3. Вариант A — одно окно, две вкладки (**рекомендуется**)

Правая кнопка → пункт меню → **окно «Узел coordinator»** с вкладками:

- **«Состояние»** — только чтение: состояние, источник, отчёт, сессия (+ привязка),
  следующий запуск, ветка, назначение. Кнопки «Привязать текущую» и «Отвязать»
  действуют сразу — это не правка полей.
- **«Настройки»** — то же окно, что утверждено в 0018: id, роль, провайдер/модель,
  назначение, пресет (чтение), расписание, связи, «Сохранить», «Удалить узел».
  Одна кнопка «Сохранить» и один диалог «изменено · не сохранено».

Пункты меню: **«Состояние узла»** и **«Настройки узла»** — оба открывают это же
окно, первый на вкладке «Состояние», второй на «Настройки». Прежнее название
«Сведения об узле» уходит: сведения (роль, модель, назначение, связи) теперь
в настройках, а состояние — на первой вкладке.

Почему рекомендуется:

- буквально «в одном месте с настройками»: одно окно и один путь;
- один путь записи (уже существующий), состояние нельзя поправить случайно —
  оно только для чтения;
- минимальная правка кода: добавить вкладку в `renderNodeEditModal()`, перенести
  строки из `renderDetails()`, убрать их из нижней панели; API и данные не меняются;
- форма окна утверждена в 0018 — крестик, Esc, подтверждение при правках уже есть.

Минусы: на один клик больше, чем сейчас; состояние не видно «наведением», пока
окно закрыто; окно закрывает канву.

## 4. Вариант B — панель под кнопкой «...»

На карточке появляется кнопка **«...»** (в правом верхнем углу, на месте точки
активности; работа по-прежнему видна зелёной рамкой и словом). Клик по ней или
правая кнопка открывают **панель 392 px** прямо под кнопкой:

- сверху — состояние: источник, отчёт, сессия, следующий запуск, ветка;
- ниже — поля настроек: id (чтение), роль, модель, назначение, пресет (чтение);
- внизу — «Сохранить» и «Связи…» (связи и расписание остаются в полном окне).

Плюсы: один клик; канва и соседние карточки остаются на месте; кнопка «...» видна,
путь не надо помнить.

Минусы: второй редактор и второй путь записи рядом с полным окном — легко получить
две правды и потерять «изменено · не сохранено»; 392 px не вмещают связи и
расписание, поэтому «одно место» получается неполным; панель закрывает соседние
карточки; кнопка на каждой карточке спорит с точкой активности.

## 5. Рекомендация

**Вариант A.** Задача — свести состояние и настройки в одно место; A делает это
одним окном с одним сохранением и переиспользует уже утверждённую форму 0018.
B быстрее на один клик, но заводит второй редактор; его сильную сторону —
«состояние видно сразу» — можно позже добавить строкой состояния в само меню,
не ломая A.

## 6. Поведение и доступность

- Вкладки — `role="tab"`/`aria-selected`, стрелки ←/→ переключают, Home/End —
  первая/последняя; Esc закрывает окно и возвращает фокус на карточку узла.
- Вкладка «Состояние» только для чтения; «Привязать текущую»/«Отвязать» пишут
  сразу и сообщают результат в существующую живую область, без «Сохранить».
- Пустые состояния называются словами, как сейчас: «нет данных» (активность ещё
  не получена), «нет отчёта», «не привязана», «расписание выкл». Панель не
  выдумывает «свободен», если активность не пришла.
- Ошибка записи остаётся в окне и говорит тремя частями: что, почему, что сделать.
- В B панель ограничивается краями канвы (тот же `clampPopover`), закрывается
  Esc и кликом мимо; фокус остаётся на кнопке «...».
